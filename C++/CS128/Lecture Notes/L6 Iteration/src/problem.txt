Overview
A packing line stamps every package with an integer serial number, and the line's scanner does three jobs. 
It totals a sample of serials to sign a batch, it sums the digits of one serial to make a checksum, and it 
folds that checksum until a single digit remains. Each job repeats a step until a condition ends it: a 
for-statement over a stride, a while-statement that consumes its own operand, and a while-statement wrapped 
around a repeated process.

Write BatchSignature, DigitSum, and ChecksumFolds, the three functions the scanner runs.

Functions to Implement
int BatchSignature(int first, int last, int step);
Returns the sum of the serials first, first + step, first + 2 * step, and so on, for every serial that is at most 
last. When first > last, no serial is scanned and the result is 0. step is always at least 1.
int DigitSum(int serial);
Returns the sum of the decimal digits of serial, which is never negative.
int ChecksumFolds(int serial);
Returns how many times serial must be run through DigitSum, the return value becoming the next input, until the 
result is a single digit, meaning less than 10. A serial that is already a single digit needs 0 folds, and serial 
is never negative.
Taking a number apart: The remainder and division operators do the work. serial % 10 is the last digit, 
and serial / 10 is the number without it.

Reusing your own work: Calling your own DigitSum inside ChecksumFolds is allowed, because a function you have 
written is a tool you may use. Repeating the digit loop inside ChecksumFolds also passes.

Stopping boundaries: A serial that lands exactly on last is scanned, and 10 is the smallest value that needs a fold.

The loop variable is a serial, not an index: In BatchSignature it starts at first and is compared against last,
both of which are int, so it is declared int as well.

Examples
Example 1: Traversing first to last by step
BatchSignature(4, 12, 5)  // returns 13, scanning 4 and 9;
                          // the next serial, 14, is past 12
BatchSignature(6, 6, 4)   // returns 6
BatchSignature(11, 4, 3)  // returns 0
Example 2: Summing the decimal digits
DigitSum(407)  // returns 11
DigitSum(60)   // returns 6
Example 3: Folding to a single digit
ChecksumFolds(8888)  // returns 2: the value moves from
                     // 8888 to 32 to 5
Constraints
Write all three function bodies in src/solution.cc. includes/solution.hpp provides the declarations this activity 
requires, and those declarations must not be changed. You may add functions of your own, provided you declare each 
one in includes/solution.hpp as well as define it in src/solution.cc. A rule below that requires a definition to 
contain a loop or a function call means that function's own definition, not a function it calls.
Each function must contain a loop. This is enforced: a function without a for-statement, while-statement, or 
do-statement is rejected before any test runs.
Every loop changes something its condition reads, or it never ends.
None of the three reads input or prints anything. src/driver.cc calls all three with values you may change to 
experiment, and is not graded.
Ten of the hundred points are for clear code, two for each of five checks: the program compiles without warnings, 
every variable you declare is initialized and used, each function stays within the course's size and complexity 
limits, identifiers follow the course's naming conventions, and the code reads clearly. Readability and naming are 
the two to watch here. The digit base is a number that carries a meaning, so a bare 10 inside DigitSum or 
ChecksumFolds costs those points. Name it as a constant. Spell a constant you name kLikeThis. Ask a container 
empty() rather than comparing its size() with 0. Use a bool on its own rather than comparing it with true or false, 
and do not use an int where a bool is meant.
Compiled with clang++ under -std=c++20 -Wall -Wextra -Werror -pedantic. Function definitions belong in 
src/solution.cc, not in the header. The tests are compiled with AddressSanitizer and UndefinedBehaviorSanitizer, 
which diagnose memory errors and some forms of undefined behavior; neither detects every invalid operation.
