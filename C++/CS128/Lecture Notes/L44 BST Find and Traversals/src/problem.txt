BST Find and Traversals

Recall how a BST insertion routes by comparing the new value to each visited node and choosing the left or right fork; the same descent logic, retargeted, drives lookup. This activity collects the query and traversal methods that a useful BST exposes: a search by value, a minimum and maximum, a height query, and the three classical orderings (inorder, preorder, postorder). Each builds on the same recursive shape applied to a different ordering of the visit.

TNode<T>
Each node in the tree is a provided TNode<T> holding a value and left and right child pointers. Your query and traversal code reads these fields as it traverses the tree.

Public data members
value | T | Provided. The value stored in the node.
left | TNode<T>* | Provided. Left child, or nullptr.
right | TNode<T>* | Provided. Right child, or nullptr.

How Find works
Traverse from the root, comparing target with the current node's value. When they match, return &current->value. When target is less, follow current->left; when greater, follow current->right. A traversal that reaches nullptr has exhausted the search; return nullptr to signal "not found".

How FindMin and FindMax work
The smallest value in a BST sits at the leftmost node, and the largest at the rightmost. Starting at the root, follow left pointers until none remain (for the minimum) or follow right pointers until none remain (for the maximum); return a pointer to that node's value. An empty tree has no such node and returns nullptr.

Why const T* rather than bool or T
Returning a pointer lets a single value distinguish "found" from "not found" while also handing the caller a handle to the stored value. A plain bool answers only the existence question; a plain T cannot represent "there is no value to return" for an empty tree without inventing a sentinel. The pointer is const so the caller cannot edit the stored value through it; mutating a node's value in place would silently break the BST ordering invariant.

How the traversals work
Each traversal visits every node exactly once, distinguished only by the relative order of three steps: visiting the current node, recursing on the left subtree, and recursing on the right subtree. Inorder produces left, current, right; preorder produces current, left, right; postorder produces left, right, current. For a BST, the inorder traversal produces the stored values in sorted order; preorder produces the root first; postorder produces the root last.

How Height works
Height is defined recursively over subtrees. The empty subtree has height -1 by convention, which makes the recurrence work cleanly for leaves. Any non-empty subtree's height equals one more than the larger of its children's heights. The public method delegates to the private helper passing root_; the helper returns -1 for nullptr, otherwise 1 + max(Height(node->left), Height(node->right)).

Example
Insert 10, 5, 15, 3, 7, 12, 20:
       10
      /  \
     5    15
    / \   / \
   3   7 12  20

Find(7)        -> pointer to 7
Find(8)        -> nullptr
FindMin()      -> pointer to 3
FindMax()      -> pointer to 20
Height()       -> 2
InorderTraversal()   -> [3, 5, 7, 10, 12, 15, 20]
PreorderTraversal()  -> [10, 5, 3, 7, 15, 12, 20]
PostorderTraversal() -> [3, 7, 5, 12, 20, 15, 10]

Constraints
Your code must compile with clang++ using the c++20 standard without errors under -Wall -Wextra -Werror -pedantic.
You may include only the following headers: "tnode.hpp", "find_bst.hpp", <iostream>, <vector>.
Search the tree and compute the traversals, minimum, maximum, and height yourself by traversing the nodes; you may not use library search or algorithm functions to do the work for you.
