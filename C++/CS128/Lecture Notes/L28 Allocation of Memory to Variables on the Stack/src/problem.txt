A screen-time app converts a day's phone pickups to minutes with DailyScreenTime. In a typical implementation, each function call of DailyScreenTime pushes a stack frame that holds its parameters and its local variables, and compiled code reaches each of them at a fixed offset from where the frame is. In the course's build, that position is kept in a register called the frame pointer.

int DailyScreenTime(int morning_pickups, int evening_pickups) {
  const int kMorningMinutes = MinutesOnScreen(morning_pickups);
  const int kEveningMinutes = MinutesOnScreen(evening_pickups);
  return kMorningMinutes + kEveningMinutes;
}
The class FrameOffsets lays out one stack frame in a simple model. In the model, a frame holds its objects in declaration order, parameters first, with no space between them. An object's offset N is the sum of the sizes, in bytes, of the objects up to and including it, and the object is at fp-N: its lowest byte is N bytes below the frame pointer. A first object of 4 bytes is therefore at fp-4. The frame's size is the sum of the sizes of all its objects.

Object of DailyScreenTime	Size in bytes	Offset
morning_pickups	4	fp-4
evening_pickups	4	fp-8
kMorningMinutes	4	fp-12
kEveningMinutes	4	fp-16
The frame of DailyScreenTime is therefore 16 bytes in the model. The class models a frame and is not how the machine stores one. A compiler may order the objects differently and may leave space between them, and a real frame also holds more than its parameters and local variables.

An object is run-time-sized when its size is known only while the program runs, as for a built-in array whose number of elements is a parameter. A run-time-sized local array is not standard C++. Clang accepts one as an extension, which the course's compilation flags reject. In a typical implementation, a frame's size is a number the compiler writes into the instructions when it compiles the function, so a run-time-sized object would make it a value computed while the program runs. In the model, the offset of a run-time-sized object depends on its own size, and so does the offset of every object after it. The objects before it keep their offsets.

FrameObject
A FrameObject is a struct whose members describe one object of a frame.

Public data members of FrameObject
Member	Type	Description
name	std::string	The object's name. No two objects of a frame have the same name.
size	unsigned int	The object's size in bytes, or 0 when the object is run-time-sized. Its in-class member initializer is = 0.
size_known	bool	true when the object's size is known when the program is compiled, and false when the object is run-time-sized. Its in-class member initializer is = true.

Public interface
Signature	Description
FrameOffsets() = default;	The default constructor, declared = default. A frame constructed with it has no objects.
bool AddObject(const std::string& name, unsigned int size);	Appends an object named name of size bytes, whose size_known is true, after every object already in the frame, run-time-sized or not, and returns true. bool OffsetOf(const std::string& name, unsigned int* offset) const;	Stores the offset N of the object named name in the object that offset points to, and returns true. It returns false, and stores nothing, when offset is nullptr, when the frame has no object named name, or when that object's offset is not known. It calls IndexOf and OffsetKnown.
const FrameObject* ObjectAt(unsigned int offset) const;	Returns the address of the element of objects_ whose offset is known and equal to offset, not the address of a copy. It returns nullptr when no known offset equals offset: for 0, for a value that falls inside an object, and for a value past every known offset. It calls OffsetKnown.
bool FrameSize(unsigned int* size) const;	Stores the frame's size, the sum of the sizes of all its objects, in the object that size points to, and returns true. A frame with no objects has size 0. It returns false, and stores nothing, when size is nullptr or when the frame holds a run-time-sized object. It calls OffsetKnown.
