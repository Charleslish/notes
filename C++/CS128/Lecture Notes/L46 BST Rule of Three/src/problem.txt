BST Rule of Three

Recall that a class which owns dynamic memory needs three coordinated functions to behave correctly when copied or destroyed: the destructor, the copy constructor, and the copy assignment operator. Together they are the Rule of Three. This activity implements all three on a BST whose nodes are allocated with new, so the class owns the entire forest of nodes reachable from root_. Two private recursive helpers do the structural work: Clear postorder-deletes a subtree, and CopyTree preorder-allocates a deep copy. The destructor calls Clear, the copy constructor calls CopyTree, and copy assignment combines both with a self-assignment check at the top.

Each TNode carries a parent pointer in addition to left and right. The provided Insert sets all three when it adds a node; your copy must preserve parent across the deep copy so the resulting tree is structurally identical and self-consistent.

TNode<T>
Each node is a provided TNode<T> carrying its value and three pointers. CopyTree allocates new nodes and sets these fields; Clear deletes them.

right | TNode<T>* | Provided. Right child, or nullptr.
parent | TNode<T>* | Provided. Parent node, or nullptr for the root. Your deep copy must reproduce this pointer on every copied node.

How Clear works
The pattern is postorder recursion. When node is nullptr, return. Otherwise, clear the left subtree first, then clear the right subtree, then delete the current node. Reversing the order (deleting the current node before the children) leaves node->left and node->right pointing into freed memory, and the next recursive call dereferences a dead node. The destructor's body is a single call to Clear(root_).

How CopyTree works
The pattern is preorder recursion: allocate the current node first, then recurse on each child. When node is nullptr, return nullptr so the caller assigns nullptr to the appropriate child link. Otherwise, allocate a new TNode<T> with the same value, set its parent to the supplied parent, recursively copy the left subtree (passing the new node as the parent), recursively copy the right subtree (also passing the new node as the parent), and return the new node. The two recursive calls return pointers that the caller stores in left and right; passing the just-allocated node as the parent argument is what keeps every parent pointer correct in the deep copy.

How operator= works
The body has four steps in order:
1. Self-assignment guard: when this == &other, return *this immediately. Without this check, step 2 would destroy the source before step 3 could read it.
2. Release the existing tree by calling Clear(root_).
3. Rebuild as a deep copy: root_ = CopyTree(other.root_, nullptr).
4. Return *this.

Example
Source tree built from: 20, 10, 30, 5, 15
             20
           /    \
         10      30
        /  \
       5   15

BinarySearchTree<int> copy(source);
  CopyTree recursively allocates 5 new nodes; parent pointers
  match the source's structure. Inorder of copy: 5, 10, 15, 20, 30
  (identical to source). Every address in copy differs from source.

source.Insert(25);
  source now has 6 nodes. copy is unchanged (still 5 nodes).

BinarySearchTree<int> dest;
dest.Insert(100);
dest = source;
  Step 1: this != &source, so do not return.
  Step 2: Clear(root_) releases dest's old node (value 100).
  Step 3: root_ = CopyTree(source.root_, nullptr) allocates 6 new nodes.
  Step 4: return *this.
  dest's inorder: 5, 10, 15, 20, 25, 30.

Constraints
Your code must compile with clang++ using the c++20 standard without errors under -Wall -Wextra -Werror -pedantic.
You may include only the following headers: "tnode.hpp", "binary_search_tree.hpp", <iostream>, <vector>.
Implement the copy and teardown yourself with the recursive helpers; you may not use library algorithm functions to do the work for you.
