L8 The Preprocessor, the Linker, and Overloading
    From source files to a program
        Turning those files into one running program takes four stages: 
        1.preprocessor: it reads a source file and carries out every directive that begins with #, 
            producing the expanded text the next stage actually sees. 
            That expanded text is called a translation unit, and it is what the rest of the pipeline works on
        2.compiler: translates that text into assembly, a low-level language that names the processor's own operations one at a time
        3.assembler: translates the assembly into machine code, one object file for each source file
        4.linker: it joins the object files into one runnable program, pairing each function call with its definition
    The include guard
        C++ requires that a class, an enumeration, or a function be defined no more than once in a translation unit
        An include guard prevents the second copy: skipped on every inclusion after the first one
            #ifndef FUNCTIONS_HPP //survive only if the macro FUNCTIONS_HPP is not yet defined
            #define FUNCTIONS_HPP //From this point on, FUNCTIONS_HPP is defined
            #endif  // closes the include guard
    The header and its source file
    Function overloading

L11-2 Maps
    std::map
    From membership to association
        std::map stores key-value pairs.
        Each key appears at most once, and looking up a key produces the value stored with it
    Declaring a std::map
        #include <map>
        A declaration names two types between angle brackets, the key type and then the value type,
        std::map<std::string, int> inventory;
        std::map<std::string, int> ages {{"grace", 51}, {"ada", 36}};
        size() empty()
        a map keeps its pairs in sorted order, and the order is decided by the keys alone
    Growing a map with insert()
        container.insert({key, value})
        if the key is already present, the map is unchanged and the stored value remains
    Reading with at()
        ages.at("ada")//36
        at() never inserts: 
            it produces the stored value, and a missing key stops the program rather than changing the map
        Whether a key is present at all is asked as it is asked of a set: 
            contains(key) produces true exactly when the map holds the key
    Writing with []
        The statement inventory["apples"] = 6
            stores 6 with the key "apples", creating the pair if the key is new and overwriting the value if it is not
    The read that writes
        std::map<std::string, int>
        [] on a missing key writes
        If a key is not found, it is entered into the map with a default value for its value, 
            and [] produces that value: [] is little more than a convenient notation for insert()
        [] for building a map, overwriting a value, or counting
        Reading a map:
            with at() or 
            behind a contains() guard and reserves [] for statements that write, or
            find()
        const std::map<std::string, int> ages {{"ada", 36}};
        std::cout << ages["ada"] << std::endl;
        //error, [] may insert a pair, and a const map cannot change, so a const map provides no []. 
    Traversing a map
        for (const auto& [item, count] : stock)
            item names one pair's key and count names its value for one iteration
            std::map<std::string, int> stock {{"pens", 8}, {"apple", 3}, {"kiwi", 5}};
            use structured binding to traverse
            for (const auto& [item, count] : stock)
                std::cout << item << " " << count << std::endl;
            //apple 3\nkiwi 5\npens 8
            or, use .first and .second to reach the key and value
            for (const auto& roster : rosters)
                std::cout << roster.first << " "<< roster.second << std::endl;

            const on the key records that a stored key never changes
            auto is a placeholder for that type
    The counting idiom

    Set and map elements
        auto& id is also accepted over set: 
            auto deduces const int from the element access, so id has type const int&. 
            It does not provide a way to modify the set element. 
            The familiar const auto& id states the read-only intent explicitly.
        For std::map<std::string, int>, the element type is std::pair<const std::string, int>
            We can modify the mapped value through reference, but not the key.
    Reference lifetime and invalidation
        If the lifetime ends while the reference remains, we have a dangling reference
        A vector can replace its element storage while the vector object itself remains alive. 
            Its size is the number of elements it holds; 
            its capacity is the number of elements its current allocation can accommodate without reallocation
            To make reallocation explicit, we will use a member function: reserve()
                readings.reserve(requested_capacity) ensures a capacity of at least requested_capacity
            readings.capacity() + 1 requests more than the current capacity, so a successful function call forces this case
            std::vector<int> readings{4, 8, 15};
            int& first = readings[0];
            readings.reserve(readings.capacity() + 1); 
            //The original element's lifetime ends, so first no longer refers to a live element.
            first = 3;//error
        Erasing an element shifts the elements after it toward the beginning of the vector. 
            References at or after the erased element become invalid
        Grow with resize() without reallocating 
            remain valid.
        Shrink with resize()
            	References to removed elements become invalid; references to retained elements remain valid.
